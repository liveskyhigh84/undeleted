### MindWalk — when it earns its keep

```bash
mindwalk                      # serve UI, pick a session
mindwalk open <session.jsonl> # replay one specific session
mindwalk map <repo>           # 3D city of any repo, no session needed
mindwalk analyze <session> --judge claude   # grade the run
```

Sessions live in `~/.claude/projects/<slug>/*.jsonl`.

`analyze` is the part that matters — it runs a judge over a finished session and grades
whether the agent explored before editing, stayed in scope, and verified its own work.
Every finding links to that moment on the timeline. That is a code review *of the agent*.

**Use it for:** a sprawling agent change where a flat diff doesn't show the shape of what
happened; comparing how Claude explores a task vs how Codex does; auditing whether an agent
wandered outside the scope you set.

**Don't use it for:** a two-line fix. Read the diff. The tool is v0.3, reads Claude Code and
Codex logs only (no Cursor), and its own launch thread on Hacker News argued it is closer to
fun than essential. Treat it as an audit lens, not a review tool.

### ai-tells-validator — the copy gate

```bash
node ~/.claude/skills/ai-tells-validator/scripts/validate.mjs < draft.txt   # exit 1 = tells found
node ~/.claude/skills/ai-tells-validator/scripts/rewrite.mjs  < draft.txt   # clean until it passes
```

Run on any prose a reader would distrust if it read as ChatGPT default: landing-page copy,
cold email, sequences, social posts, founder announcements.

**Do not** run it on code comments, commit messages, or long-form technical docs — the
rule-of-three pattern it flags is genuinely useful there, and the false-positive rate is high.

**Ordering with the existing stack** (this is an addition, not a replacement):
1. `ai-tells-validator` — deterministic regex, catches the mechanical tells, gateable in CI
2. `ai-tell-detector` — the judgment pass on structure and rhythm
3. `humanizer` — rewrite whatever both flagged
4. `/stop-slop` — final prose pass

The validator goes first precisely because it is dumb and fast. Let it strip the obvious
before spending model tokens on the subtle.

### Session memory — what already covers it

The "give Claude infinite memory via Google's free research tool" idea is a **wrap-up routine**:
file each finished session somewhere retrievable, then pull the one relevant piece next time
instead of re-pasting the whole history.

Most of that is already installed and running:

| Layer | Already covers it |
|---|---|
| Cross-session facts | `~/.claude/projects/*/memory/` + `MEMORY.md` index |
| Semantic recall | `supermemory` MCP (`/supermemory-search`) |
| Session snapshots | `/save-session` and `/resume-session` |
| Per-project state | `memory.md` in each project root |
| Source-grounded research | `/notebooklm` skill (660 lines, installed) |

The genuinely missing piece is the **handoff between them**: nothing currently files a finished
session into NotebookLM as a durable, queryable source. When a project accumulates enough
sessions that `memory.md` stops being scannable, run `/notebooklm` to load that project's
`memory.md` + run logs as sources — you get retrieval plus free audio overviews and mind maps
off the same corpus. Do this per-project and on demand, not on a schedule; a NotebookLM
notebook per session is noise, not memory.
